
# Работа с дисками, разделами и файловыми системами в Linux

### 1. Просмотр содержимого файла /etc/fstab

Для просмотра конфигурации файловых систем была выполнена команда:

```bash
cat /etc/fstab
```

Исходное содержимое файла до изменений:

```text
proc            /proc                   proc    nosuid,noexec,gid=proc                          0 0
devpts          /dev/pts                devpts  nosuid,noexec,gid=tty,mode=620,ptmxmode=0666    0 0
tmpfs           /tmp                    tmpfs   nosuid                                          0 0
UUID=93c203a1-7a96-4cd1-a5f8-ed900f7b23ab       /       ext4    defaults        1 1
```

Файл `/etc/fstab` содержит информацию о файловых системах, которые должны монтироваться при загрузке операционной системы. В нём указываются источник файловой системы, точка монтирования, тип файловой системы и параметры монтирования.

### 2. Добавление виртуального диска

В виртуальную машину был добавлен дополнительный виртуальный диск объёмом 5 ГБ.

Для определения типа виртуализации была выполнена команда:

```bash
systemd-detect-virt
```

Результат:

```text
kvm
```

Это означает, что виртуальная машина работает под управлением KVM.

### 3. Определение блочных устройств

Для просмотра подключённых устройств была использована команда:

```bash
lsblk
```

Результат:

```text
NAME   MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
sda      8:0    0 31.6G  0 disk
└─sda1   8:1    0 31.6G  0 part /
sdb      8:16   0    5G  0 disk
sdc      8:32   0    5G  0 disk
sr0     11:0    1    4M  0 rom
sr1     11:1    1 1024M  0 rom
```

Для дальнейшей работы был выбран диск `/dev/sdb` объёмом 5 ГБ.

Дополнительно была выполнена команда:

```bash
sudo fdisk -l /dev/sdb /dev/sdc
```

Она подтвердила, что оба устройства являются виртуальными дисками QEMU HARDDISK объёмом 5 ГиБ.

### 4. Создание таблицы разделов и раздела

Для создания таблицы разделов была запущена утилита:

```bash
sudo fdisk /dev/sdb
```

В интерактивном режиме были выполнены следующие команды:

- `g` - создание таблицы разделов GPT;
- `n` - создание нового раздела;
- `w` - сохранение изменений.

В результате была создана таблица разделов GPT с GUID:

```text
73F3297D-E13E-44B4-A21A-735739D54984
```

Был создан один раздел:

```text
/dev/sdb1
```

Тип раздела - Linux filesystem.

Размер раздела - 5 ГиБ.

После создания была выполнена команда:

```bash
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINT
```

Результат:

```text
NAME    SIZE TYPE FSTYPE  M
sda    31.6G disk
└─sda1 31.6G part ext4    /
sdb       5G disk
└─sdb1    5G part
sdc       5G disk
sr0       4M rom  iso9660
sr1    1024M rom
```

### 5. Создание файловой системы ext4

На созданном разделе была создана файловая система ext4:

```bash
sudo mkfs.ext4 /dev/sdb1
```

В результате команда успешно завершилась.

Полученный UUID файловой системы:

```text
162af206-802a-46e6-a5b8-63188d91332c
```

### 6. Создание каталога и ручное монтирование

Для монтирования файловой системы был создан отдельный каталог:

```bash
sudo mkdir -p /mnt/data
```

Затем файловая система была смонтирована:

```bash
sudo mount /dev/sdb1 /mnt/data
```

Проверка результата:

```bash
findmnt /mnt/data
```

Полученный вывод:

```text
TARGET    SOURCE    FSTYPE OPTIONS
/mnt/data /dev/sdb1 ext4   rw,relatime
```

Это подтверждает успешное монтирование раздела `/dev/sdb1` в каталог `/mnt/data`.

### 7. Создание тестовых файлов

На смонтированном разделе были созданы три тестовых файла:

```bash
sudo touch /mnt/data/file1.txt /mnt/data/file2.txt /mnt/data/test.txt
```

Для просмотра содержимого каталога была выполнена команда:

```bash
ls -la /mnt/data
```

Результат:

```text
total 24
drwxr-xr-x 3 root root  4096 Nov  1 13:30 .
drwxr-xr-x 3 root root  4096 Nov  1 13:28 ..
-rw-r--r-- 1 root root     0 Nov  1 13:30 file1.txt
-rw-r--r-- 1 root root     0 Nov  1 13:30 file2.txt
drwx------ 2 root root 16384 Nov  1 13:27 lost+found
-rw-r--r-- 1 root root     0 Nov  1 13:30 test.txt
```

Все три файла успешно созданы на дополнительном диске.

Каталог `lost+found` создаётся автоматически при создании файловой системы ext4.

### 8. Проверка содержимого после размонтирования

Для отключения файловой системы была выполнена команда:

```bash
sudo umount /mnt/data
```

После этого содержимое каталога было проверено командой:

```bash
ls -la /mnt/data
```

Результат:

```text
total 8
drwxr-xr-x 2 root root 4096 Nov  1 13:28 .
drwxr-xr-x 3 root root 4096 Nov  1 13:28 ..
```

После размонтирования каталог `/mnt/data` оказался пустым.

Это объясняется тем, что после отключения файловой системы каталог снова отображает содержимое родительской файловой системы. Созданные файлы не удаляются, а остаются на разделе `/dev/sdb1`.

Таким образом, эксперимент подтвердил, что файлы физически хранятся на дополнительном разделе, а не непосредственно в каталоге монтирования корневой файловой системы.

### 9. Определение UUID файловой системы

Для получения UUID была выполнена команда:

```bash
sudo blkid /dev/sdb1
```

Результат:

```text
/dev/sdb1: UUID="162af206-802a-46e6-a5b8-63188d91332c" BLOCK_SIZE="4096" TYPE="ext4" PARTUUID="1d422e11-c5d0-425d-a5cb-0b0b7a27953b"
```

Полученный UUID был использован для настройки автоматического монтирования.

### 10. Настройка автоматического монтирования через /etc/fstab

Для добавления новой записи использовалась команда:

```bash
echo 'UUID=162af206-802a-46e6-a5b8-63188d91332c /mnt/data ext4 defaults 0 2' | sudo tee -a /etc/fstab
```

В файл `/etc/fstab` была добавлена следующая строка:

```text
UUID=162af206-802a-46e6-a5b8-63188d91332c /mnt/data ext4 defaults 0 2
```

В записи указаны:

- UUID файловой системы;
- точка монтирования `/mnt/data`;
- тип файловой системы `ext4`;
- параметры монтирования `defaults`;
- значение `0` для резервного копирования с помощью dump;
- значение `2` для проверки файловой системы при загрузке.

Использование UUID позволяет идентифицировать файловую систему независимо от имени устройства.

### 11. Проверка корректности конфигурации

Для проверки файла `/etc/fstab` была выполнена команда:

```bash
sudo findmnt --verify --verbose
```

В выводе были обнаружены все необходимые точки монтирования, включая `/mnt/data`.

Для дополнительной проверки система подтвердила:

```text
UUID=162af206-802a-46e6-a5b8-63188d91332c translated to /dev/sdb1
source /dev/sdb1 exists
FS type is ext4
```

Итоговый результат:

```text
Success, no errors or warnings detected
```

После проверки была выполнена команда:

```bash
sudo mount -a
```

Она завершилась без ошибок и примонтировала файловую систему согласно настройкам `/etc/fstab`.

Для проверки автоматического монтирования виртуальная машина была перезагружена:

Файловая система автоматически смонтировалась после перезагрузки, а все ранее созданные файлы сохранились.

## Дополнительная проверка прав доступа

После выполнения основных пунктов лабораторной работы была обнаружена проблема: пользователь `student` не имел прав на создание файлов в каталоге `/mnt/data`.

Для исправления владельцем каталога был назначен пользователь `student`:

```bash
sudo chown student:student /mnt/data
```

Проверка:

```bash
ls -ld /mnt/data
```

Результат:

```text
drwxr-xr-x 3 student student 4096 Nov  1 13:48 /mnt/data
```

После этого от имени пользователя `student` был создан дополнительный файл:

```bash
touch /mnt/data/student_test.txt
```

В файл была записана информация:

```bash
echo 'Linux test' > /mnt/data/student_test.txt
```

Чтение содержимого:

```bash
cat /mnt/data/student_test.txt
```

Результат:

```text
Linux test
```

Проверка с помощью `stat` подтвердила, что владельцем файла является `student`, а права доступа составляют `0644`.
