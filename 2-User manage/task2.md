# Запрещаем

## 1. Запретите пользователю `user1` из предыдущего задания выполнять вход в систему

Для блокировки пароля пользователя `user1` была выполнена команда:

```bash
sudo passwd -l user1
```

Команда `passwd -l` блокирует пароль учётной записи, добавляя признак блокировки в поле пароля.

## 2. Покажите, как именно вы это сделали, и как проверить состояние учётной записи

Для проверки состояния учётной записи была выполнена команда:

```bash
sudo passwd -S user1
```

Результат:

```text
Locked password, yescrypt encryption.
```

Сообщение `Locked password` подтверждает, что пароль пользователя заблокирован.

Дополнительно была выполнена команда:

```bash
getent passwd user1
```

Результат:

```text
user1:x:1001:1002::/home/user1:/bin/bash
```

В выводе отображаются имя пользователя, UID, основной GID, домашний каталог и используемая оболочка.

Существует и другой способ запретить интерактивный вход - назначить пользователю оболочку `/sbin/nologin`:

```bash
sudo usermod -s /sbin/nologin user1
```

Проверка:

```bash
getent passwd user1
```

Результат:

```text
user1:x:1001:1002::/home/user1:/sbin/nologin
```

Оболочка `/sbin/nologin` запрещает обычный интерактивный вход через оболочку. После проверки исходная оболочка была восстановлена командой:

```bash
sudo usermod -s /bin/bash user1
```

## 3. Какие ещё способы запретить интерактивный вход существуют?

Помимо блокировки пароля и назначения оболочки `/sbin/nologin`, можно использовать следующие способы:

1. **Ограничение через PAM.** С помощью модуля PAM `pam_access.so` и файла `/etc/security/access.conf` можно настроить правила, запрещающие вход определённым пользователям. Для этого модуль должен быть подключён в соответствующей конфигурации PAM.
2. **Ограничение входа по SSH.** В конфигурации SSH-сервера `/etc/ssh/sshd_config` можно использовать директиву `DenyUsers user1`, чтобы запретить этому пользователю подключаться по SSH. После изменения конфигурации необходимо проверить её корректность и применить настройки сервера.
3. **Блокировка пароля.** Команда `sudo passwd -l user1` запрещает аутентификацию по паролю, но сама по себе не гарантирует запрет всех возможных способов входа, например через SSH-ключи.

Выбор метода зависит от того, какие именно способы входа требуется запретить.

## 4. Можно ли создать двух пользователей с одинаковым именем?

В обычной локальной базе учётных записей Linux нельзя корректно создать две разные учётные записи с одинаковым именем. Имя пользователя должно однозначно определять учётную запись.

При этом в системе могут существовать учётные записи из разных источников идентификации, например из локальной базы и сетевого каталога. В таком случае возможны конфликты имён, поэтому следует обеспечивать уникальность имён пользователей.

## 5. Можно ли создать двух пользователей с одинаковым UID? Что при этом покажет система?

Да, в Linux можно создать двух пользователей с одинаковым UID, если при создании указать параметр `-o`, разрешающий неуникальный идентификатор.

Для проверки была выполнена команда:

```bash
sudo useradd -o -u 1001 user2
```

Команда создала пользователя `user2` с UID `1001`, совпадающим с UID пользователя `user1`.

Проверка обеих учётных записей:

```bash
getent passwd user1 user2
```

Результат:

```text
user1:x:1001:1002::/home/user1:/bin/bash
user2:x:1001:1005::/home/user2:/bin/bash
```

Из вывода видно, что обе учётные записи имеют одинаковый UID `1001`, но разные основные GID и домашние каталоги.

Дополнительная проверка:

```bash
id user1
```

Результат:

```text
uid=1001(user1) gid=1002(user1) groups=1002(user1),10(wheel),1004(labusers)
```

Команда:

```bash
id user2
```

Результат:

```text
uid=1001(user1) gid=1005(user2) groups=1002(user1)
```

В выводе `id user2` система показывает `uid=1001(user1)`, потому что UID `1001` также принадлежит `user1` в базе учётных записей и разрешение числового идентификатора в имя становится неоднозначным.

**Последствия одинакового UID:**

- С точки зрения прав доступа к файлам оба пользователя рассматриваются как один и тот же владелец, поскольку система ориентируется на числовой UID.
- Пользовательские процессы с этим UID имеют одинаковую идентичность владельца для большинства проверок прав доступа.
- Различия в основных GID и дополнительных группах могут приводить к разным результатам проверки групповых прав.
- Возникает неоднозначность при отображении имени владельца файлов и информации об учётных записях.

Поэтому назначать одинаковые UID обычным пользователям не рекомендуется.

## 6. Восстановите возможность входа пользователя `user1` в систему

Для разблокировки пароля была выполнена команда:

```bash
sudo passwd -u user1
```

Затем состояние пароля было проверено командой:

```bash
sudo passwd -S user1
```

Результат:

```text
Password set, yescrypt encryption.
```

Сообщение подтверждает, что пароль больше не заблокирован.

Дополнительно была восстановлена стандартная оболочка пользователя:

```bash
sudo usermod -s /bin/bash user1
```

Проверка:

```bash
getent passwd user1
```

Результат:

```text
user1:x:1001:1002::/home/user1:/bin/bash
```

Таким образом, пароль пользователя `user1` разблокирован, а оболочка `/bin/bash` восстановлена. Это подтверждает восстановление настроек учётной записи, необходимых для обычного входа.
