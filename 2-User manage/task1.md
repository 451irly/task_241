# Управление пользователями

## 1. Добавить пользователей `user1` и `user2`

Созданы две учётные записи с домашними каталогами:

```bash
sudo useradd -m -s /bin/bash user1
sudo useradd -m -s /bin/sh user2
```

### 1.1. Для `user1` установить оболочку Bash

Команда создания `user1` содержит параметр `-s /bin/bash`.

Проверка:

```console
[student@student-04 ~]$ getent passwd user1
user1:x:1001:1002::/home/user1:/bin/bash
```

### 1.2. Для `user2` установить оболочку sh

Команда создания `user2` содержит параметр `-s /bin/sh`.

Проверка:

```console
[student@student-04 ~]$ getent passwd user2
user2:x:1002:1003::/home/user2:/bin/sh
```

Вывод подтверждает, что для `user1` указана оболочка `/bin/bash`, а для `user2` - `/bin/sh`. Позже учётная запись `user2` была удалена в соответствии с пунктом 8.

### 1.3. Установить пароли пользователям

```bash
sudo passwd user1
sudo passwd user2
```

Обе команды завершились сообщением `passwd: all authentication tokens updated successfully`.

## 2. Создать группу `labusers`

Группа создана командой:

```bash
sudo groupadd labusers
```

### 2.1. Добавить `user1` в группу системных администраторов

В данной системе используется группа `wheel`.

```bash
sudo usermod -aG wheel user1
```

Проверка состава группы:

```console
[student@student-04 ~]$ getent group wheel
wheel:x:10:root,student
```

Членство `user1` в группе `wheel` дополнительно подтверждено командой `id user1` в пункте 10.

### 2.2. Добавить `user1` и `user2` в группу `labusers`

```bash
sudo usermod -aG labusers user1
sudo usermod -aG labusers user2
```

Проверка до удаления `user2`:

```console
[student@student-04 ~]$ getent group labusers
labusers:x:1004:user1,user2
```

## 3. Объяснить права доступа и вывести права в домашнем каталоге одного пользователя

В Linux права доступа обычно задаются отдельно для владельца файла, группы-владельца и остальных пользователей.

- `r` (*read*) - чтение файла. Для каталога - просмотр списка его содержимого.
- `w` (*write*) - изменение файла. Для каталога - создание, удаление и переименование записей при соблюдении остальных условий доступа.
- `x` (*execute*) - запуск файла как программы, если это исполняемый файл. Для каталога - возможность проходить через каталог и обращаться к объектам внутри него.

Команда для просмотра содержимого домашнего каталога `user1`:

```bash
sudo ls -la /home/user1
```

Результат:

```console
total 56
drwx------ 8 user1 user1 4096 Oct 18 09:09 .
drwxr-xr-x 5 root  root  4096 Oct 18 09:10 ..
-rw------- 1 user1 user1  217 Jul 26  2021 .bash_logout
-rw------- 1 user1 user1  259 Jul 26  2021 .bash_profile
-rw------- 1 user1 user1  188 Jul 26  2021 .bashrc
drwx------ 2 user1 user1 4096 Jul 26  2021 .cache
drwx------ 2 user1 user1 4096 Jul 26  2021 .config
drwx------ 3 user1 user1 4096 Oct  7  2025 .local
-rw------- 1 user1 user1   17 Jul 26  2021 .lpoptions
-rw------- 1 user1 user1  121 Jul 26  2021 .rpmmacros
drwx------ 3 user1 user1 4096 Oct  7  2025 .mutt
drwx------ 2 user1 user1 4096 Jul 26  2021 .ssh
-rwx------ 1 user1 user1  319 Jul 26  2021 .xprofile
drwx------ 2 user1 user1 4096 Jul 26  2021 .xsession.d
```

Права `drwx------` у каталога `/home/user1` означают, что владелец может просматривать и изменять содержимое и проходить через каталог, а группа и остальные пользователи не имеют таких прав по обычным битам разрешений.

## 4. Создать файл, доступный для чтения всем, но для записи - только владельцу

Создан файл `/home/user1/labfile.txt`, владельцем назначен `user1`, а права установлены в `644`.

```bash
sudo touch /home/user1/labfile.txt
sudo chown user1:user1 /home/user1/labfile.txt
sudo chmod 644 /home/user1/labfile.txt
```

Результат:

```console
[student@student-04 ~]$ sudo ls -l /home/user1/labfile.txt
-rw-r--r-- 1 user1 user1 0 Oct 18 09:34 /home/user1/labfile.txt
```

Права `644` означают: владелец может читать и изменять файл (`rw-`), а группа и остальные пользователи могут только читать (`r--`).

### 4.1. Временно установить права `777`

```bash
sudo chmod 777 /home/user1/labfile.txt
```

Результат:

```console
[student@student-04 ~]$ sudo ls -l /home/user1/labfile.txt
-rwxrwxrwx 1 user1 user1 0 Oct 18 09:34 /home/user1/labfile.txt
```

### 4.2. Объяснить, почему права `777` избыточны

Права `777` предоставляют владельцу, группе и всем остальным пользователям чтение, запись и выполнение. Для обычного текстового файла право выполнения не требуется, а разрешение на запись для всех пользователей позволяет любому из них изменять содержимое. Это нарушает принцип минимально необходимых прав.

### 4.3. Вернуть минимально необходимые права

```bash
sudo chmod 644 /home/user1/labfile.txt
```

Проверка после восстановления:

```console
[student@student-04 ~]$ sudo ls -l /home/user1/labfile.txt
-rw-r--r-- 1 user1 user1 0 Oct 18 09:34 /home/user1/labfile.txt
```

## 5. Что такое встроенная учётная запись администратора Linux?

Встроенная учётная запись системного суперпользователя называется `root`. Обычно её UID равен `0`. У неё широкие административные полномочия для управления системой, пользователями, службами и файлами.

## 6. Как выполнить одну команду с правами администратора?

Для запуска отдельной команды с повышенными привилегиями используется `sudo`. Например:

```console
[student@student-04 ~]$ sudo whoami
root
```

Вывод `root` показывает, что команда выполнилась с полномочиями суперпользователя.

## 7. Может ли суперпользователь выполнить абсолютно любую операцию? Привести пример ограничения, не связанного с обычными правами файлов

Не всегда. Хотя `root` имеет широкие полномочия, некоторые операции ограничиваются ядром Linux, механизмами изоляции процессов, состоянием устройства или особенностями виртуальных файловых систем. Например, попытка записать данные в память процесса через `/proc/1/mem` может быть отклонена ядром, даже если команда запущена через `sudo`.

Проверка в системе:

```console
[student@student-04 ~]$ sudo sh -c 'echo test > /proc/1/mem'
sh: line 1: echo: write error: Input/output error
```

Операция завершилась ошибкой ввода-вывода. Это пример ограничения, которое нельзя объяснить только обычными битами прав доступа файла.

## 8. Удалить пользователя `user2`, сохранив домашний каталог, и доказать, что учётная запись удалена

Пользователь удалён без параметра `-r`, поэтому домашний каталог сохранён:

```bash
sudo userdel user2
```

Проверка учётной записи:

```console
[student@student-04 ~]$ id user2
id: ‘user2’: no such user
```

Проверка сохранённого домашнего каталога:

```console
[student@student-04 ~]$ sudo ls -ld /home/user2
drwx------ 8 1002 1003 4096 Oct 18 09:10 /home/user2
```

Команда `id` сообщает, что учётная запись `user2` не существует, а каталог `/home/user2` по-прежнему присутствует. Числовые UID и GID отображаются потому, что соответствующие имена больше не разрешаются системой.

## 9. Как изменить владельца и группу файла или каталога? Изменить владельца файла из пункта 4

Для изменения владельца и группы используется команда `chown` в формате `chown ВЛАДЕЛЕЦ:ГРУППА ФАЙЛ`.

Для данного файла выполнено:

```bash
sudo chown student:labusers /home/user1/labfile.txt
```

Проверка:

```console
[student@student-04 ~]$ sudo ls -l /home/user1/labfile.txt
-rw-r--r-- 1 student labusers 0 Oct 18 09:34 /home/user1/labfile.txt
```

Результат подтверждает, что владельцем стал `student`, группой-владельцем - `labusers`. Права доступа остались `rw-r--r--`.

## 10. Вывести UID, основной GID и дополнительные группы пользователя `user1`

Команда:

```console
[student@student-04 ~]$ id user1
uid=1001(user1) gid=1002(user1) groups=1002(user1),10(wheel),1004(labusers)
```

- **UID:** `1001`.
- **Основной GID:** `1002` (`user1`).
- **Дополнительные группы:** `wheel` (GID `10`) и `labusers` (GID `1004`).
