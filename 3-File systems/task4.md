# RAID-массивы

### 1. Что такое RAID и какие основные уровни RAID вы знаете?

**RAID (Redundant Array of Independent Disks)** - технология объединения нескольких физических дисков в единый логический массив для повышения производительности, надёжности хранения данных или сочетания этих характеристик.

Основные уровни RAID:

- **RAID 0** - чередование блоков данных между дисками (Striping). Увеличивает производительность и объединяет ёмкость дисков, но не обеспечивает отказоустойчивость.
- **RAID 1** - зеркалирование данных (Mirroring). Информация одновременно записывается на несколько дисков, что позволяет сохранить данные при отказе одного из них.
- **RAID 5** - распределение данных и контрольной информации между дисками. Требует минимум три диска и допускает отказ одного диска.
- **RAID 6** - аналог RAID 5 с двойной чётностью. Требует минимум четыре диска и допускает отказ двух дисков.
- **RAID 10** - сочетание зеркалирования и чередования данных. Обычно требует минимум четыре диска.

### 2. Добавьте в виртуальную машину два дополнительных диска.

Для работы использовались два виртуальных диска объёмом по 5 ГБ:

- `/dev/sdb` - 5 ГБ;
- `/dev/sdc` - 5 ГБ.

Проверка дисков:

```bash
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINT
```

На каждом диске была создана таблица разделов GPT и один раздел, занимающий практически всё доступное пространство:

```bash
sudo fdisk /dev/sdb
sudo fdisk /dev/sdc
```

В интерактивном режиме использовались команды:

- `g` - создание таблицы GPT;
- `n` - создание раздела;
- `Enter` - значения по умолчанию;
- `w` - сохранение изменений.

В результате созданы разделы `/dev/sdb1` и `/dev/sdc1`.

Для управления программными RAID-массивами установлена утилита mdadm:

```bash
sudo apt-get install mdadm
```

### 3. На двух дисках создайте RAID0-массив средствами Linux software RAID.

Создание RAID0:

```bash
sudo /usr/sbin/mdadm --create /dev/md0 --level=0 --raid-devices=2 /dev/sdb1 /dev/sdc1
```

В результате создан массив `/dev/md0`, использующий два раздела.

### 4. Проверьте состояние массива.

Проверка состояния:

```bash
cat /proc/mdstat
sudo /usr/sbin/mdadm --detail /dev/md0
```

Результат:

- RAID Level: `raid0`;
- Array Size: `9.99 GiB`;
- Raid Devices: `2`;
- Active Devices: `2`;
- Failed Devices: `0`;
- State: `clean`.

Оба раздела `/dev/sdb1` и `/dev/sdc1` успешно вошли в состав массива.

### 5. Создайте файловую систему ext4 уже на RAID-устройстве и примонтируйте её.

Создание файловой системы:

```bash
sudo mkfs.ext4 /dev/md0
```

Создание точки монтирования:

```bash
sudo mkdir -p /mnt/raid0
```

Монтирование массива:

```bash
sudo mount /dev/md0 /mnt/raid0
```

Проверка:

```bash
findmnt /mnt/raid0
```

Результат:

```text
TARGET     SOURCE   FSTYPE
/mnt/raid0 /dev/md0 ext4
```

### 6. Запишите на массив тестовые файлы.

Создание тестового файла:

```bash
sudo sh -c 'echo "RAID0 test file" > /mnt/raid0/test.txt'
```

Проверка чтения:

```bash
cat /mnt/raid0/test.txt
```

Результат:

```text
RAID0 test file
```

Проверка доступного пространства:

```bash
df -h /mnt/raid0
```

Результат:

- общий размер - 9,8 ГБ;
- занято - 2,1 МБ;
- доступно - 9,3 ГБ.

### 7. Удалите RAID0 и создайте RAID1.

Сначала массив был размонтирован:

```bash
sudo umount /mnt/raid0
```

Затем остановлен:

```bash
sudo /usr/sbin/mdadm --stop /dev/md0
```

Проверка:

```bash
cat /proc/mdstat
```

Старые RAID-метаданные очищены:

```bash
sudo /usr/sbin/mdadm --zero-superblock /dev/sdb1 /dev/sdc1
```

Проверка отсутствия метаданных:

```bash
sudo /usr/sbin/mdadm --examine /dev/sdb1 /dev/sdc1
```

Результат:

```text
mdadm: No md superblock detected on /dev/sdb1.
mdadm: No md superblock detected on /dev/sdc1.
```

Создание RAID1:

```bash
sudo /usr/sbin/mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdb1 /dev/sdc1
```

При создании был включён внутренний write-intent bitmap для ускорения восстановления массива после отказов.

### 8. Создайте файловую систему на RAID1 и снова проверьте чтение/запись.

Проверка состояния массива:

```bash
cat /proc/mdstat
sudo /usr/sbin/mdadm --detail /dev/md0
```

Полученные характеристики:

- RAID Level: `raid1`;
- Array Size: `4.99 GiB`;
- Raid Devices: `2`;
- Active Devices: `2`;
- Failed Devices: `0`;
- State: `clean`.

Обозначение `[UU]` подтверждает работоспособность обоих устройств.

Создание файловой системы ext4:

```bash
sudo mkfs.ext4 /dev/md0
```

Создание точки монтирования:

```bash
sudo mkdir -p /mnt/raid1
```

Монтирование:

```bash
sudo mount /dev/md0 /mnt/raid1
```

Проверка:

```bash
findmnt /mnt/raid1
```

Создание тестового файла:

```bash
sudo sh -c 'echo "RAID1 test file" > /mnt/raid1/test.txt'
```

Проверка чтения:

```bash
cat /mnt/raid1/test.txt
```

Результат:

```text
RAID1 test file
```

Проверка доступного пространства:

```bash
df -h /mnt/raid1
```

Результат:

- общий размер - 4,9 ГБ;
- занято - 1,3 МБ;
- доступно - 4,6 ГБ.

### 9. В чём практическая разница между RAID0 и RAID1?

| Характеристика | RAID0 | RAID1 |
|---|---|---|
| Принцип работы | Чередование блоков данных | Зеркалирование данных |
| Минимум дисков | 2 | 2 |
| Полезная ёмкость двух дисков по 5 ГБ | Около 10 ГБ | Около 5 ГБ |
| Производительность чтения | Повышенная | Может быть повышенной |
| Производительность записи | Повышенная | Обычно сопоставима с одним диском |
| Отказоустойчивость | Отсутствует | Переживает отказ одного диска |

RAID0 обеспечивает более эффективное использование общей ёмкости дисков и повышение производительности, но при отказе одного диска весь массив становится недоступен.

RAID1 дублирует данные на обоих дисках, поэтому при отказе одного устройства информация остаётся доступной на втором. При этом полезная ёмкость массива равна объёму одного диска.

### 10. Имитируйте отказ одного диска RAID1:

#### 10.1. пометьте диск как неисправный;

Для имитации отказа `/dev/sdb1` выполнена команда:

```bash
sudo /usr/sbin/mdadm /dev/md0 --fail /dev/sdb1
```

Проверка состояния:

```bash
cat /proc/mdstat
sudo /usr/sbin/mdadm --detail /dev/md0
```

Результат:

- State: `clean, degraded`;
- Active Devices: `1`;
- Failed Devices: `1`;
- `/dev/sdb1` - `faulty`;
- `/dev/sdc1` - `active sync`;
- обозначение массива - `[_U]`.

#### 10.2. удалите его из массива;

Удаление неисправного раздела:

```bash
sudo /usr/sbin/mdadm /dev/md0 --remove /dev/sdb1
```

Результат:

```text
mdadm: hot removed /dev/sdb1 from /dev/md0
```

#### 10.3. убедитесь, что данные остаются доступны.

Проверка тестового файла:

```bash
cat /mnt/raid1/test.txt
```

Результат:

```text
RAID1 test file
```

Файл успешно прочитан после удаления неисправного раздела. Данные остались доступны благодаря работе второго диска `/dev/sdc1`.

### 11. Верните диск в массив или добавьте новый и наблюдайте процесс восстановления

Возвращение раздела `/dev/sdb1` в массив:

```bash
sudo /usr/sbin/mdadm /dev/md0 --add /dev/sdb1
```

Результат:

```text
mdadm: re-added /dev/sdb1
```

Проверка состояния:

```bash
cat /proc/mdstat
```

Результат:

```text
md0 : active raid1 sdb1[0] sdc1[1]
      5235712 blocks super 1.2 [2/2] [UU]
```

Для дополнительной проверки восстановления была повторно смоделирована неисправность `/dev/sdb1`, после чего раздел удалён из массива:

```bash
sudo /usr/sbin/mdadm /dev/md0 --fail /dev/sdb1
sudo /usr/sbin/mdadm /dev/md0 --remove /dev/sdb1
```

Во время работы массива на одном диске был записан дополнительный файл размером 128 МиБ:

```bash
sudo dd if=/dev/zero of=/mnt/raid1/rebuild-test.bin bs=1M count=128 status=progress
```

После этого раздел был повторно добавлен:

```bash
sudo /usr/sbin/mdadm /dev/md0 --add /dev/sdb1
```

Проверка состояния массива:

```bash
cat /proc/mdstat
sudo /usr/sbin/mdadm --detail /dev/md0
```

Финальное состояние:

- State: `clean`;
- Active Devices: `2`;
- Working Devices: `2`;
- Failed Devices: `0`;
- `/dev/sdb1` - `active sync`;
- `/dev/sdc1` - `active sync`;
- обозначение массива - `[UU]`.

Проверка сохранности файлов:

```bash
cat /mnt/raid1/test.txt
ls -lh /mnt/raid1/rebuild-test.bin
```

Тестовый файл сохранился, дополнительный файл размером 128 МиБ присутствует.

После повторного добавления диска массив вернулся в состояние `clean`. Отдельный этап `recovery` в `/proc/mdstat` зафиксировать не удалось, поскольку проверка была выполнена уже после восстановления рабочего состояния массива.

### 12. Какие файловые системы могут самостоятельно обеспечивать функции, похожие на RAID?

**Btrfs** - файловая система Linux, поддерживающая работу с несколькими устройствами, зеркалирование данных и различные профили распределения информации.

**ZFS** - файловая система и система управления томами, поддерживающая зеркалирование, RAIDZ и контроль целостности данных.

Обе системы имеют встроенные механизмы управления несколькими дисками и обеспечения отказоустойчивости.

### 13. Можно ли создать RAID во время установки Linux?

Да, программный RAID можно создать непосредственно во время установки Linux, если установщик дистрибутива поддерживает работу с программными RAID-массивами.

Для этого необходимо выбрать несколько физических дисков, создать на них разделы, объединить их в RAID-массив и затем создать файловую систему на полученном логическом устройстве.

Также существует аппаратный RAID, который настраивается средствами RAID-контроллера до установки операционной системы.
